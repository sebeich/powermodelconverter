# UC5 Diagnosis

## Scope

This note records the root-cause analysis for the unbalanced AC-OPF stage of UC5. The
three-way conversion/validation legs (pandapower `runpp_3ph`, OpenDSS,
PowerModelsDistribution) were green from the start; both defects below sat in the
optimization model setup, not in pmc's converters.

## 1. Per-unit scaling: `sbase_default`

First symptom: Ipopt crawled through hundreds of iterations with dual infeasibility around
`1e10`–`1e11` and step sizes near `1e-7`, with no convergence in either the ACP or the IVR
formulation.

PowerModelsDistribution itself logs the hint:

- `basemva=100 is the default value, you may want to adjust sbase_default for better convergence`

The DSS parser defaults the power base to 100 MVA (`sbase_default = basemva * 1e3` kVA).
The IEEE European LV feeder carries on the order of 100 kW — a three-orders-of-magnitude
mismatch that puts every power variable around `1e-3`–`1e-5` pu and conditions the KKT
system badly.

### Fix

`docs/examples/uc5/mc_opf.jl`: set `data["settings"]["sbase_default"] = 100.0` (kVA units,
i.e. a 100 kVA base) right after parsing.

## 2. Voltage-bound units: the ENGINEERING model expects SI, not per unit

Second symptom: with sane scaling, both the ACP and the IVR OPF terminated with
`EXIT: Converged to a point of local infeasibility`, at any cap value (`1.05`, `1.10`).

The cap had been written into the ENGINEERING data model as `bus["vm_ub"] = 1.10` per
terminal — but the ENGINEERING model carries voltage bounds in SI units (kV), not per
unit. On the 11 kV medium-voltage source bus that turned the intended `1.10 pu` cap into a
1.10 kV ceiling on a ~6.35 kV phase-ground voltage: structurally infeasible no matter how
much PV is curtailed. (On the 0.416 kV feeder buses the same number was a non-binding
2.6 pu, which is why the infeasibility localized so confusingly.)

Isolation: removing the cap entirely made the same model solve to optimality with all
275 kW of PV dispatched and 207 kW of reverse flow into the MV grid — proving the
generators, costs, and bounds were all healthy and only the voltage constraint was broken.

### Fix

`docs/examples/uc5/mc_opf.jl`: apply the cap on the MATHEMATICAL model, where bus `vmax`
is expressed in per unit of each bus base, and exempt the reference bus:

```julia
math = PMD.transform_data_model(data)
for (_, bus) in math["bus"]
    get(bus, "bus_type", 1) == 3 && continue
    bus["vmax"] = min.(bus["vmax"], vm_ub)
end
```

The solution is mapped back to engineering names with `PMD.transform_solution`.

The cap value itself was set to `1.10 pu` (the EN 50160 +10% supply band) rather than the
source setpoint `1.05 pu`, which would leave no headroom above the feeder's own operating
point. The PV scenario density is a 5 kW single-phase unit at every load bus (55 units,
275 kW against a ~55 kW off-peak load), producing reverse-flow voltage rise toward the cap
at the feeder extremities.

## Result

See `summary.json` (regenerated by `run.py`): the ACP unbalanced OPF terminates
`LOCALLY_SOLVED`, and the per-phase curtailment split is reported in
`curtailment_table.csv`.

## Conclusion

Both findings are model-preparation pitfalls on the optimization side of the toolchain
seam: per-unit base selection when crossing from distribution-scale data into a
transmission-default solver stack, and the distinction between an operating setpoint and a
regulatory voltage band when turning a simulation snapshot into an optimization problem.
Neither required changes to pmc's adapters; both are now encoded in the reproducer.
